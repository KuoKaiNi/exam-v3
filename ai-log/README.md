# AI 使用紀錄

## 這是 AI 試考

這份答案是 **AI（Claude Opus 5.5，在 Claude Code 裡執行）自己作答**的，用途是讓主考官看 AI 照題目作答會做到什麼程度、題目哪裡不清楚。沒有真人考生參與寫程式。

- 我沒辦法對自己用 `/export` 匯出完整對話，所以這裡放的是摘要：做了哪些重要決定、我自己寫錯又修正的地方。
- 逐步的操作時間表另外記在主考官指定的工作紀錄檔（不在 repo 裡）。
- 實際操作找到的問題在 `../TESTLOG.md`；看不懂題目、先自己假設的地方在 `../questions.md`。

## 重要決定

| 決定 | 為什麼 |
|---|---|
| Spring Boot 3.5.16、Java 17、Thymeleaf | 題目建議 Spring Boot 3；3.5.16 是 Maven Central 上 3.x 最新版。Boot 4.2 已經出了，但沒有必要冒換大版本的風險 |
| 資料庫用 H2 檔案模式 | 主考官要在另一台電腦照 README 啟動，不用裝資料庫或 Docker 最不容易出錯。資料表一樣用 Flyway 建 |
| 先反編譯 App 1.0（jadx）再寫 API | 規格只寫回應格式。看了 App 才知道：張數填 1.5 時送字串 `"1.5"`、空白送 `null`、整數欄位收到小數會報「資料格式錯誤」、總計的 `return_pct` 允許 null。所以請求內容自己解析，不用 Spring 預設轉換（預設會把 1.5 捨成 1，錯誤格式也不是 App 認得的） |
| 新增時同時查上市、上櫃，哪邊先找到就回 | 10 秒限制。證交所要節流（每 2 秒一次），上櫃股不該等證交所 |
| 「找不到」和「查不到」分開 | 兩邊都正常回「沒有資料」才算代號不存在（404）；有一邊連不上就回 503 不儲存，不把網路問題當成代號不存在 |
| 清單只讀快取，背景依「應該已公布的最近交易日」判斷要不要重查 | 題目要求不能每次開清單都查官方，但官方公布後一小時內要看得到。平日 13:30 後還沒拿到當天收盤價的，每 20 分鐘重查一次 |
| 看到 403、429、轉址、HTML 就暫停查那個網站 10 分鐘 | 證交所被擋後一段時間都查不到，繼續查只會被擋更久 |
| 「現在」一律用 `Asia/Taipei` 的 Clock | 正式機的時區不是台北。首頁時間、判斷今天是不是交易日、這個月是幾月都用台北時間 |
| 收盤價也存進資料庫，記下來源主機 | 重啟後不用整頁「未取得」；換成主考官的測試伺服器時不沿用舊主機的資料 |
| 覆寫 Tomcat、Jackson、log4j-api 的修補版 | Spring Boot 3.5.16 預設版本有 51 筆已知弱點，同系列修補版可以修掉 48 筆 |

## AI 自己寫錯、後來修正的地方

| 錯在哪 | 怎麼發現 | 怎麼修 |
|---|---|---|
| JdbcClient 用預設的屬性對應，H2 每讀一列就記一筆「找不到 buyPrice 欄位」的例外到 trace 檔 | 手動操作後看到 `data/holdings.trace.db` | 改成自己寫 RowMapper（TESTLOG 3） |
| 沒想到使用者會打全形數字代號 | 手動用表單送 `２３３０` | 代號先做 NFKC 正規化（TESTLOG 2） |
| 新增時要等證交所查完才看櫃買中心的結果，上櫃股多等 2 秒以上 | 實測計時 | 改成任一邊先找到就回（TESTLOG 4） |
| 改上一項時寫出競態 bug：兩邊都查完的回呼可能比「找到了」先跑，而那段判斷沒考慮已經找到，結果上市股被誤報「官方查不到」 | 實測新增 1101 失敗 | 判斷改成先看有沒有找到；補一個讓證交所故意慢回的測試，先確認舊程式會失敗再修（TESTLOG 5） |
| 想用 `git stash` 暫時還原舊程式來證明新測試抓得到 bug，但檔案是新加的、還沒被 git 追蹤，stash 沒作用 | stash 後測試仍全過、`git stash list` 是空的 | 改成先複製一份、手動改回舊邏輯再跑 |
| 有一個測試數請求次數，沒考慮上櫃那條查詢在背景還沒跑完，結果偶爾多算 | 測試失敗訊息 | 改成只數證交所的請求，連跑三次確認穩定 |
| 收盤價只放記憶體，重啟後整頁「未取得」約 20 秒 | 重啟後馬上開清單 | 存進資料庫（TESTLOG 7） |
| 工作紀錄有幾列的時間是 AI 自己估的，沒有照規定用 `date` 取，還出現比實際晚的時間 | 對照 `date` 輸出時發現 | 改成實際寫入時的 `date` 時間並標「補記」 |
| 模擬器設定伺服器網址時，輸入法跳出來讓「儲存」按鈕位置改變，第一次按到別的地方 | 截圖看到網址沒變 | 打完字後重新讀畫面元件位置再按 |

## Part B 的重要決定

| 決定 | 為什麼 |
|---|---|
| 先實際抓 TWT49U、exDailyQ 再設計 | 題目只說「除權除息計算結果表」。抓下來才發現證交所只有「權值+息值」合計，不能直接當現金股利；明細要從「詳細資料」欄找到 TWT49UDetail |
| 按年抓整個市場、存進資料庫，算股利時只讀資料庫 | 官方 API 不能只查一檔；一年約 1 MB，放在新增交易的請求裡做會超過 App 的 10 秒 |
| 股利不存結果，每次用「交易＋官方資料」重算 | 題目要求補登、修改、刪除後股利跟著變；存結果就要處理一致性 |
| 交易時間軸：同一天先除權息再交易、先買後賣 | 「前一個交易日收盤時的持股」＝除權息日之前所有交易的結果，不需要休市日曆 |
| 寫入時鎖住那一檔再用整條時間軸檢查賣超 | 手機和電腦同時操作；補登更早的賣出、刪掉更早的買進都可能讓之後賣超 |
| Idempotency-Key 存在資料庫、處理中的重送等第一次做完 | App 10 秒逾時就重送，而第一次記新代號要查官方最多 8 秒，很容易兩個請求同時在跑 |
| App 1.0 的 API 規格完全不動，用「只有一筆買進」對應 | 三成使用者半年後還在用 1.0；實測升級前後 1.0 的回應逐字相同 |
| 回報二加「預估補充保費」，不扣進總報酬 | 題目定義總報酬用現金股利；補充保費依身分不一定扣 |

## Part B 裡 AI 自己寫錯、後來修正的地方

| 錯在哪 | 怎麼發現 | 怎麼修 |
|---|---|---|
| `IdempotencyService` 寫了兩個建構子，Spring 選不出用哪個，所有 Spring 測試都起不來 | 跑測試 | 公開的建構子加 `@Autowired` |
| Part A 的 `QuoteService.lookup`：「找到了」和「兩邊都查完」兩個回呼都會寫快取，後到的把查詢時間蓋掉 | Part B 跑全部測試時 `QuoteServiceTest` 偶爾失敗 | 改成只有真的完成結果的一方寫快取。第一次改的時候我把 record 當成可以繼承的類別寫，編譯前自己看出來重寫 |
| migration 測試用指定 id 插 1.0 的資料，H2 自動編號沒前進，誤以為新資料 id 會撞 | 測試失敗訊息 | 是測試寫錯：正式的 1.0 資料都是自動編號。改用自動編號建資料 |
| 網頁明細頁用 `th:if` 跟 `th:replace` 放在同一個元素，`th:replace` 先處理，條件沒作用，買進列顯示「未取得」 | 用 Chrome 截圖看畫面 | 外面包 `th:block th:if`（TESTLOG 11） |
| 證交所明細查了持有前的除權息 | 看伺服器記錄 | 只查第一筆交易之後的（TESTLOG 12） |
| 每股股利輸出成 `0E-8` | 寫 API.md 時看原始 JSON | 去掉多餘的 0、Jackson 用一般寫法（TESTLOG 14） |
| 補充保費一開始只用現金股利算 | 讀健保署文件原文，寫的是「含現金股利及股票股利」 | 計算基礎加上股票股利面額（每股 10 元），補測試 |
| `UPGRADE.md` 寫「0050 在 2025 年 6 月 1 拆 4」是憑記憶 | 交付前自己檢查哪些句子沒有來源 | 查證後補上日期與來源 |
| 工作紀錄又寫了「21:3x」這種估計時間 | 寫完自己看 | 改成寫入當下的 `date` 時間並標「補記」 |
| zsh 不會把變數裡的空白拆開，`adb` 指令與座標計算失敗兩次 | 指令錯誤訊息 | 改用 `ANDROID_SERIAL` 環境變數、直接用讀到的座標 |
